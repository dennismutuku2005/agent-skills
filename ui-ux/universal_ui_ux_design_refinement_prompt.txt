## 6. BUTTONS: CREATE ONE SHARED BUTTON SYSTEM

1. Primary.
2. Secondary.
3. Outline.
4. Ghost.
5. Destructive.
6. Link.
7. Icon-only.

### Standard button sizes

Support:

- Small.
- Medium.
- Large.

Standardize:

- Height.
- Padding.
- Typography.
- Font weight.
- Border radius.
- Icon size.
- Icon spacing.
- Border thickness.
- Hover state.
- Active state.
- Focus state.
- Disabled state.
- Loading state.

Do not allow individual pages to invent their own button styles.

Use variants for legitimate differences.

### Mandatory button loading behavior

This is a strict design requirement.

Every asynchronous button action must support a proper loading state.

Examples:

- Login.
- Registration.
- Save.
- Update.
- Delete.
- Create.
- Upload.
- Submit.
- Payment processing.
- API requests.
- Form submissions.

When an action starts:

1. Disable the button.
2. Prevent duplicate submissions.
3. Display a spinner in the exact center of the button.
4. Hide the normal button label while loading.
5. Keep the original button dimensions.
6. Keep the original button background.
7. Maintain proper spinner contrast.
8. Avoid layout shifts.
9. Restore the original label when the operation finishes.

Correct behavior:

Normal:

[ Save Changes ]

Loading:

[     ◌     ]

Incorrect behavior:

[ ◌ Loading... ]

[ Loading ]

[ Save Changes... ]

Never display a spinner followed by a loading word.

Never place the spinner beside the original label.

Never allow the button to grow or shrink when loading starts.

The spinner must be visually centered horizontally and vertically.

Use one shared loading implementation.

Do not implement different loading behaviors on different pages.

For icon-only buttons, center the spinner inside the existing button dimensions.

## 16. DESIGN PRINCIPLES

Apply these principles throughout the application.

VISUAL HIERARCHY:
Important information must attract attention first.

CONSISTENCY:
Similar components must look and behave alike.

PROXIMITY:
Related information must be visually grouped.

ALIGNMENT:
Elements must follow intentional alignment patterns.

CONTRAST:
Use contrast to establish hierarchy and readability.

REPETITION:
Reuse established visual patterns.

SIMPLICITY:
Remove unnecessary interface elements.

BALANCE:
Avoid crowded or excessively empty layouts.

WHITESPACE:
Use spacing to improve readability and separation.

PREDICTABILITY:
Users should understand how the interface behaves.

FEEDBACK:
Important interactions must provide clear feedback.

ACCESSIBILITY:
The interface must work for different users and interaction methods.
